### The Problem: Planar Flatness vs. Spherical Geometry

When flight paths and orbital ground tracks are drawn as straight lines on standard Web Mercator (EPSG:3857) maps, they deceive human perception. The Mercator projection is conformal—it preserves local angles $\frac{\partial y}{\partial \phi} = \sec\phi$ at the expense of severe areal distortion that explodes toward the poles as $\sec^2\phi \to \infty$.

A straight line drawn between two points on a Mercator map is not a geodesic (the shortest path on Earth); it is a **Rhumb line (loxodrome)**—a path of constant compass azimuth that spirals around the globe. In orbital mechanics and high-speed aerospace navigation, spacecraft follow great circles governed by the Riemannian 2-sphere metric:

$$ds^2 = R^2 \left( d\phi^2 + \cos^2\phi \, d\lambda^2 \right)$$

where $R = 3,958.8\text{ miles}$ ($6,371.0\text{ km}$).


### Mathematical Derivation of the Spherical Geodesic

#### 1. Haversine Central Angular Distance
Given two points $P_1(\phi_1, \lambda_1)$ and $P_2(\phi_2, \lambda_2)$ in radians, the central angle $\Delta\sigma$ is derived from the spherical law of cosines reformulated via the Haversine identity to prevent numerical instability at small separations:

$$\sin^2\left(\frac{\Delta\sigma}{2}\right) = \sin^2\left(\frac{\phi_2 - \phi_1}{2}\right) + \cos\phi_1 \cos\phi_2 \sin^2\left(\frac{\lambda_2 - \lambda_1}{2}\right) \equiv a$$

$$\Delta\sigma = 2 \cdot \operatorname{atan2}\left(\sqrt{a}, \sqrt{1 - a}\right) = 2 \arcsin(\sqrt{a})$$

The true geodesic surface distance is:

$$D_{\text{geodesic}} = R \cdot \Delta\sigma$$

#### 2. Spherical Linear Interpolation (3D Slerp)
Intermediate waypoints at progress fraction $f \in [0, 1]$ are generated by projecting latitude and longitude to 3D Cartesian coordinates on the unit sphere $S^2 \subset \mathbb{R}^3$:

$$\mathbf{v}_1 = \begin{pmatrix} \cos\phi_1 \cos\lambda_1 \\ \cos\phi_1 \sin\lambda_1 \\ \sin\phi_1 \end{pmatrix}, \quad \mathbf{v}_2 = \begin{pmatrix} \cos\phi_2 \cos\lambda_2 \\ \cos\phi_2 \sin\lambda_2 \\ \sin\phi_2 \end{pmatrix}$$

$$\mathbf{v}(f) = \frac{\sin((1 - f)\Delta\sigma)}{\sin\Delta\sigma}\mathbf{v}_1 + \frac{\sin(f\Delta\sigma)}{\sin\Delta\sigma}\mathbf{v}_2$$

Converting $\mathbf{v}(f) = (x, y, z)^T$ back to geographic coordinates:

$$\phi(f) = \operatorname{atan2}\left(z, \sqrt{x^2 + y^2}\right), \quad \lambda(f) = \operatorname{atan2}(y, x)$$

### Mathematical Derivation of the Flat Mercator Linear Chord

#### 1. Forward Conformal Projection
The Web Mercator projection maps spherical $(\phi, \lambda)$ into Cartesian $(x, y)$ space via the inverse Gudermannian function:

$$x = \lambda, \quad y = \ln\left[\tan\left(\frac{\pi}{4} + \frac{\phi}{2}\right)\right] = \operatorname{gd}^{-1}(\phi)$$

#### 2. Planar Linear Interpolation & Inverse Projection
Interpolating linearly in planar coordinates:

$$x(f) = (1 - f)x_1 + fx_2, \quad y(f) = (1 - f)y_1 + fy_2$$

$$\lambda(f) = x(f), \quad \phi(f) = 2 \arctan\left(\exp(y(f))\right) - \frac{\pi}{2} = \operatorname{gd}(y(f))$$

#### 3. Closed-Form Rhumb Line Surface Distance
The true terrestrial distance along the Mercator chord is:

$$D_{\text{mercator}} = R \sqrt{(\Delta\phi)^2 + q^2 (\Delta\lambda)^2}, \quad q = \frac{\Delta\phi}{\ln\left(\frac{\tan(\pi/4 + \phi_2/2)}{\tan(\pi/4 + \phi_1/2)}\right)}$$

### Continuous Velocity Scrubber Architecture

Traditional flight simulators restrict velocity changes to discrete steps or clock multipliers. In **Artemis Velocity Vis**, velocity is decoupled from the animation frame rate by treating the canonical flight progress $p \in [0, 1]$ as the primary spatial coordinate.

When the user scrubs the velocity slider from $500\text{ mph}$ (commercial aviation) to $25,000\text{ mph}$ (atmospheric re-entry), the position remains stationary while instantaneous ground-track rates, Mach numbers, and remaining time estimations update with zero lag.

```

      SUBSONIC                 ORBITAL LEO            LUNAR RETURN
     Mach 0.65                 Mach 22.81              Mach 31.93
 (Commercial Cruise)        (Circular Velocity)     (Artemis Skip Entry)
```

### Aerospace Kinematics Equations

1. **Standard Sea-Level Speed of Sound**:
   $$c_0 = 767.26\text{ mph} = 1,125.33\text{ ft/s} = 343.0\text{ m/s} = 1,234.8\text{ km/h}$$

2. **Mach Number Formulation**:
   $$M = \frac{v_{\text{mph}}}{767.26\text{ mph}}$$

3. **Ground-Track Velocity Vectors**:
   $$v_{\text{mps}} = \frac{v_{\text{mph}}}{3600}, \quad v_{\text{km/s}} = v_{\text{mph}} \times 0.00044704, \quad v_{\text{knots}} = v_{\text{mph}} \times 0.868976$$

4. **Continuous Clock Integration**:
   $$T_{\text{total}} = \frac{D_{\text{geodesic}}}{v_{\text{mps}}}, \quad t_{\text{elapsed}} = p \cdot T_{\text{total}}, \quad \text{ETA} = (1 - p) \cdot T_{\text{total}}$$

In the `requestAnimationFrame` tick, given delta time $\Delta t$ in seconds and simulation time multiplier $m$:

$$\Delta p = \frac{\Delta t \cdot m}{T_{\text{total}}} = \frac{\Delta t \cdot m \cdot v_{\text{mps}}}{D_{\text{geodesic}}}$$

This guarantees smooth, jitter-free animation across $60\text{Hz}$, $120\text{Hz}$, or variable refresh displays.

### The SSR Challenge in Next.js 15 & React 19

Leaflet relies directly on global browser APIs (`window`, `document`, `navigator.userAgent`) during module evaluation. Importing Leaflet at the root of a Next.js server component triggers the fatal runtime error:

```
ReferenceError: window is not defined
```

Furthermore, hydrating pre-rendered server DOM against client Leaflet canvas nodes causes React hydration mismatches.

### Zero-Side-Effect SSR Isolation Blueprint

To make `<ArtemisFlightSimulator />` a drop-in component for host applications without requiring host-level Next.js configuration, isolation is enforced internally:

```tsx
'use client';
import dynamic from 'next/dynamic';
import React, { useMemo } from 'react';
import type { MapProps } from './Map';

// Isolated client-only dynamic mount with theme-aware loading skeleton
const MapComponent = dynamic<MapProps>(() => import('./Map'), {
  ssr: false,
  loading: () => <MapLoadingFallback themeId="nasa-dark" />
});
```

### Dynamic Camera Control: Auto-Fit vs. Active Tracking

In `components/Map.tsx`, camera movement is abstracted into an internal `MapController` component hook:

1. **Overview Mode**: When switching presets or when overview is selected, `map.fitBounds(bounds, { padding: [60, 60], animate: true })` calculates the minimum bounding box enclosing both the great-circle arc and the Mercator chord.
2. **Follow Mode**: Smoothly tracks the moving spacecraft marker via `map.panTo(currentPos, { animate: true, duration: 0.3 })` without triggering redundant tile re-renders.

```tsx
function MapController({ 
  bounds, 
  currentPos, 
  cameraMode 
}: { 
  bounds: L.LatLngBounds; 
  currentPos: [number, number]; 
  cameraMode: 'follow' | 'overview'; 
}) {
  const map = useMap();
  const prevBoundsRef = useRef<string>('');

  useEffect(() => {
    const key = bounds.toBBoxString();
    if (key !== prevBoundsRef.current && cameraMode === 'overview') {
      prevBoundsRef.current = key;
      map.fitBounds(bounds, { padding: [60, 60], animate: true, duration: 0.8 });
    }
  }, [bounds, cameraMode, map]);

  useEffect(() => {
    if (cameraMode === 'follow') {
      map.panTo(currentPos, { animate: true, duration: 0.3 });
    }
  }, [currentPos, cameraMode, map]);

  return null;
}
```

### Spacecraft Heading Rotation via Spherical Trigonometry

The instantaneous spacecraft heading $\theta$ (true course bearing) is computed from the current position $\mathbf{P}(p)$ to a lookahead point $\mathbf{P}(p + \epsilon)$:

$$\theta = \operatorname{atan2}\left(\sin\Delta\lambda \cos\phi_2, \, \cos\phi_1 \sin\phi_2 - \sin\phi_1 \cos\phi_2 \cos\Delta\lambda\right)$$

This angle is injected directly into the custom `L.divIcon` marker DOM element via CSS `transform: rotate(${headingDeg}deg)`, aligning the spacecraft nosecone to the geodesic flight path in real time.
